## 1. 范围（严格四项）

### 1.1 B1 adapter 契约（投影 ↔ 模型消息）

- 定义 adapter 面：**输入**＝白名单投影（`LlmContextEvent[]`，既有类型），**输出**＝具体模型消息序列；
- 要求：① 映射是**纯函数**（同输入同输出）；② **未声明事件类型 / 未声明字段一律拒绝**（fail-closed，与全仓 schema 哲学一致）；③ 映射**不得引入预算/治理内部字段**（延续切片 1 的模型不可见约束）；④ 顺序稳定（事件流顺序 → 消息顺序）。

### 1.2 A3 多工具展开 ＋ B2 错误回填

- **多工具展开**：模型响应含 N 个工具调用 → adapter 展开为 **N 个顺序 `LlmDecision`**；loop 语义仍是"**一次决策一个工具**"；**每个工具各自过守卫 ＋ 各自过审批检查点**（**禁止**共享一次授权 —— 与 ADR-07"无配额复用"红线一致）；
- **错误回填**：工具结果（`executed` / `blocked` / `rejected` / `failed`）与审批结论（denied / advised / consumed / invalid）必须以**结构化、可理解**的形态回填给模型（含：工具名、结果类别、可读原因、可追溯引用）；**不得**把 harness 内部字段或栈信息原样透出；
- **fail-closed**：回填不得成为"绕过审批"的通道（回填内容不得被解释为授权）。

### 1.3 TEM 读闸注入点（按《TEM 接入设计》§3 落位）

- **位置**：`transformContext` 投影之后、`provider.decide()` 之前——**不得另起注入通道**；
- **条目形态**：带**来源引用**（可追溯到 Case/Claim id）；**可被 compaction 折叠，但引用链不得被吃掉**；唯一例外：`structural_preconditions`（结构前提）类**不折叠**；
- **v1 实现**：注入源为**可注入桩**（默认空 = 无记忆运行）；真实 TEM 调用在 TEM 提供接口后另批；
- **失败语义**：注入源不可用 → 记事件 ＋ **无记忆运行**（记忆是增强而非依赖）。

### 1.4 两条公理兑现（断言级）

- **durability 公理**（讨论稿 §2.3）：loop 恢复依赖的一切状态**必须可由本侧事件流推导**；**禁止**以"再查内核"为恢复依据（内核内存态在进程重启后为空，"不存在"≠"未推进"）。落地要求：把"事件流 → 恢复所需状态"写成**纯函数 ＋ 断言**（既有 `resolveCredentialState` 为范式）；
- **N1 语义边界**（**已按 owner 澄清调整**）：闸门推进的留痕 = **客户端观察事实**，其载体就是**既有 `tool/result` 事件**（记录"我方调用 `atf_gate` 并收到响应"）——**不新增事件类型**（第 13 类保持保留位）。落地要求：① 在 `session.contract.yaml` 写**语义边界注记**（`tool/result` 是客户端观察，**不是**内核状态权威副本）；② 加断言"不得以再查内核作为恢复依据"；③ 报告与文档措辞纪律。

## 2. 硬约束

- ❌ 不新增事件类型 / 退出码；不改会话协议数值；`bridge.contract.yaml` **零改动**；
- ❌ **不得放宽切片 0 守卫与切片 1 预算**；不得修改其既有断言（如需调整须提请 owner）；
- ❌ 不做真实 provider、不启 ACP、不激活 `projection`（写闸）；不接真实 TEM；
- ❌ 不改 `src/workspace/`（晋升闸 A 语义）与 `src/session/` 既有语义（除 §1.4 的注记）；
- ✅ adapter 映射与错误回填必须是**纯函数 / 结构化**（可测、可审计）；
- ✅ 多工具展开必须保证**逐个审批**（禁止批量授权）。
