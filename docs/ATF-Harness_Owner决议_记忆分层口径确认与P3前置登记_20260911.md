# ATF-Harness Owner 决议——记忆分层口径确认 + Phase 3 前置登记

**签发人**：owner
**日期**：2026-09-11
**性质**：口径确认 + 前置登记（**不产生任何当前工作项**）
**背景**：owner 提出「一个会话的上下文与记忆如何设计和管理」，并自提「至少两类：run 实例级 + 训练经验级」；owner 侧给出五层分层与三项补充分析后逐条拍板。
**结论先行**：**四项口径按建议采纳（三类记忆 / 提炼闸人工审批 / 注入可折叠但保引用 / 强制环境绑定与时效）；立稿窗口推迟到 Phase 3**。本决议不改变 Phase 2 任何已签发指令，也不授权任何记忆相关工作在 Phase 2 期间开工。

| 1 | 记忆分几类 | **三类**：run 级 / 训练经验 / 治理记忆；治理类**只补「与经验类的接口」**，不重造载体（T2 冻结合同 + 审批账本为其既有载体） |

## 2. 确认口径（Phase 3 立稿的既定起点，届时无需重新讨论）

### 2.1 分层（五层）与三类记忆归属

| 层 | 内容 | 归属 | 可变性 |
|---|---|---|---|
| ① 上下文视图 | 压缩摘要 + 承证事实原文 + 保留窗原文（compaction 投影） | harness（派生） | 可随时重建，**非记忆** |
| ② run 级记忆 | 会话事实日志（12 类事件）+ 工作区产物 T0/T1/T2 + catalog sha | harness | **append-only 不可变** |
| ③ 领域事实 | run journal 事实（内核侧） | 内核 | harness 仅以 `domain_refs` digest 引用，不留副本 |
| ④ 训练经验 | ExperienceCase（证据，不可变）→ PatternClaim（通用模式，可修订） | TEM | Case 不可变；Claim 走状态机，修订 = 新条目 + `supersedes` |
| ⑤ 治理记忆 | T2 冻结合同（G 闸门定义 / 字段规格）+ 审批账本与口径 | harness | 可变更，**须经闸 B**（决策记录 + 审批 + 原子替换） |

三分原则：**视图（可重建）／事实（不可变）／提炼物（可修订）／规则（须授权）**四者不得混同；③ 的失效方式是"被取代"，不是"被推翻"。

### 2.2 四条硬约束

1. **提炼原料只取 run 事实层（②），绝不取压缩后的上下文视图（①）**——否则记忆继承 compaction 的失真，且污染是静默的。
2. **经验条目不可原地修订**：修订 = 新条目 + `supersedes`（与 run 事实同构的 append-only 纪律）。
3. **注入上下文须带来源引用**：可被 compaction 折叠，但引用链不得被吃掉；`structural_preconditions` 类不折叠。
4. **「经验 → 规则」收敛路径**：被 validated 且涉及阈值/口径的经验，不留在经验库内生效，须上升为 T2 合同变更（走闸 B）。

### 2.3 两道闸

- **提炼闸（写入侧）**：以承证事实与 T1 晋升产物为原料；**人工审批**为裁决者；产出 ExperienceCase（不可变），多条 Case 聚合且注明失效边界后方可升级为 PatternClaim。
- **注入闸（读取侧）**：检索相关性 + 注入配额；注入条目带来源引用；折叠规则按 §2.2 第 3 条。
- **回灌闭环**：新 run 的 outcome 写回经验状态（candidate → validated / rejected / superseded）。

### 2.4 既有机制即接口（不新造）

`domain_refs` 三元组（引用不复制、天然脱敏）／compaction 承证白名单（run 事实不被上下文管理牺牲）／fsync 双档 + 尾部残段修复（事实层物理完整性 = 记忆可信前提）／闸 A 与闸 B（产物可信 + 规则可治理）／凭据一次性消费（授权事实不重复）／`projection.evidence_event` 字段位（回灌钩子，现恒 `null`）。

## 4. 当前期纪律（防夹带）

1. **Phase 2 的 S2 / S3 不得实现、预写、探索任何记忆相关工作**；不得提前激活 `projection`（其恒为 `null` 是 Phase 2 的既定状态）。
2. 本决议**不改变 Phase 2 任何已签发指令**的口径、范围与验收标准。
3. 记忆议题不进入 Phase 2 收尾验收项，仅作为 Phase 3 前置登记出现在收尾报告的待决清单中。
4. `domain_refs` / 事件 schema / 契约文件的现状口径保持不变；禁止为"将来接记忆"提前改 schema。
