## 一、两类测试

| | 开发测试 | 产品测试 |
|---|---|---|
| 维护者 | 实现方 | 验收方（独立） |
| 判据面 | 函数/组件/契约，白盒合法 | 用户可见文本、公共 API、产物文件、进程/GPU 事实 |
| 回答 | 实现对不对、改动会不会坏 | 用户现在能不能用 |
| 失败含义 | 实现错 | 产品不可用（单测全绿也算） |
| 读源码 | 不限 | 只许导航与失败归因 |

## 二、产品测试判据面

```
白名单：页面文本 / HTTP 状态与响应体 / 产物文件内容与 mtime / ps 与 nvidia-smi 事实
黑名单：内部变量、状态键、内部错误码、组件挂载信号
```

## 三、出件前三问（缺一退回）

```
1) 断言主体是哪个面？（白名单之外即不合规）
2) 读源码是导航还是判据？（判据不得引用源码符号）
3) 换实现后脚本还成立吗？（不成立＝白盒耦合）
```

## 四、证据两栏

```
观测事实：截图、页面原文、HTTP 响应、文件 mtime、进程输出 —— 可作 PASS 依据
源码推断：文件行号、状态机分支 —— 只进"断点定位"，不得进 PASS 理由
```

## 五、缺陷分流

```
分支/边界/类型错 → 开发测试补锚
链路断、状态不翻转、用户面不可见、文案泄漏内部码 → 产品测试补锚
两类都缺 → 各补一条，不得只补一层当作已修
```
