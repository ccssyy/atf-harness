## 二、核心诊断

### 2.1 一句话

**ATF 把「扩展层」和「引擎层」混在了一起。** 本应只写「DSH 没有的训练域能力」，实际重写了大量 DSH 已有的宿主机制（loop / LLM / compaction / session / fs / jobs），导致：
- 12,745 行完全重复（可删）
- vendor 治理面（spill/pruner/timeout/read-before-edit）对自研路径全部失效
- 子链与主链行为不一致（11 阶段 vs 17 段、faux 摘要 vs 真摘要）

### 2.2 历史根因（ADR-0019 原话）

> 2026-09-30 DSH 收敛裁定本意是「宿主壳＋内核自留」；实施中把 vendor 能力包族层**一并归零**——ATF src 对 vendor 60+ 能力包引用＝0。宿主基础机制全部由自研 B 档顶替。**该归零未经正式裁定。**

### 2.3 量化现状

| 维度 | 数据 |
|---|---|
| ATF 自建代码 | 45,448 行（12 模块，删死代码后） |
| **完全重复 vendor** | **12,745 行（5 模块）** |

## 三、三层审计机制（已完成，可进 CI）

```bash
npm run audit:all
# = audit:vendor-overlap  工具层（43 工具 × 699 vendor 工具名）
# + audit:module-overlap  模块层（12 模块 × 55 vendor 族）
# + audit:cross-repo-overlap 跨仓层（harness ↔ 内核）
```

**设计要点**：
- 机械枚举保证「不漏」；语义判定走显式映射表（人审固化）
- 白名单只减不增，新增重复必须显式登记理由
- **fail-closed**：vendor 树缺失/空 → 拒绝出结论（防「无重复」假绿）
- 退出码：0 = 干净；2 = 发现未登记重复

**演练留证**：注入 `atf_glob` → 准确拦下；注入新模块 → 准确拦下。

**边界（如实）**：
- 族内逐包不判（模块级结论已足够，逐包是噪音）
- 单文件内 if 密度属「架构腐化」，是另一类审计（见 §五 批次 A5）
