## 阶段 2：决策3 —— 用满 DSH 能力（2-3 天）

### 2.1 已核实的事实（纠正此前的误解）

**atf 的卡面 UI 从来就是 DSH 原生组件，atf 一行都没自己写。**

```
atf-tools 工具 execute 内
  → ctx.userQuestions.ask()          ← DSH 原生服务
  → waterfall 'user-questions/request'
  → QuestionComposer（DSH 原生 React 组件）
  → 卡片渲染
```

`grep 'userQuestions|QuestionCard|Composer' packages/extensions/atf-ui/src/*.ts` → **空**

**所以问题是"没用满 DSH 能力"，不是"仿照实现了新的"。**

### 2.2 三个动作

| 编号 | 动作 | 类型 | 工作量 | 解决什么 |
|---|---|---|---|---|
| **2-1** | `ask()` → `askTimed()`，超时转 pending | **纯用 DSH** | 半天 | zcode A3「挂起 25 分钟无超时」 |
| **2-2** | 挂 `tool-ask-user`（`mode: timed`） | **纯用 DSH** | 1 小时 | agent 有原生提问工具；聊天提问走卡 |
| **2-3** | 分组卡试点形态 B（独立 tool call） | **纯用 DSH** | 1-2 天 | zcode B1「无视强指令」、B2「pending 三层」 |

### 2.3 形态 B 的语义（关键设计）

**卡面语义分两类，不二选一：**

| 卡类型 | 例子 | 形态 | 理由 |
|---|---|---|---|
| **业务决策卡** | 分组怎么分、字段用哪些、增强几倍 | **B（独立 tool call）** | agent 应看到用户答案并据此调整 |
| **治理授权卡** | GPU 训练启动、rm 递归删、危险操作 | **A（工具内等待，保持现状）** | 不能让 agent 自己决定要不要授权 |

这个划分对应已有 `approvalExempt` 语义分类：`user_decision` → B，`governance` → A。

**为什么先试点分组卡**：
- 它是 zcode B1 的直接现场
- 语义清楚（候选制、单选）
- 改完立刻能验证"agent 能否正确使用独立提问工具"

### 2.4 验收

| 项 | 判据 |
|---|---|
| 2-1 | 构造超时场景，卡转 pending 而非永久挂起 |
| 2-2 | agent 可调用 `ask_user_question`，卡正常弹出并作答 |
| 2-3 | 真机会话：用户说"分2组"→ agent 用提问工具确认 → 分组正确落账 |
| 投影生效 | 出卡后刷新页面，卡仍在（形态 B 的卡进投影） |

### 3.2 动作

1. `_prereq(stage, *keys)` 改为调 `missing_prereqs(stage, completed_stages)`
2. `_STAGE_CTX_KEYS` 退役
3. `_completed_stages()` 从"仅回执投影"升级为"闸判定依据"
4. 补齐 `contract`/`ingest`/`register` 三段的空 `_prereq`

### 3.3 必须先做的影响面计算（动手前）

**要算出：改完之后哪些现有流程会从"能跑"变成"blocked"。**

方法：拿回放工作区（`ci-bl-test-1109-4` 等 3 个已确认在场）跑一遍全段，记录每段当前状态；改造后再跑，对比差异。

**这一步不能省** —— 否则上线才发现一批流程断掉。

## 附：两个必须先解决的前置

### 前置 A：worktree 隔离（阶段 1 之前）

```
profiles/web/node_modules/@atf/dsh-atf-tools -> /data/sam/ATF-Harness/packages/extensions/atf-tools
```

**主仓代码经 symlink 直连 dev，无构建隔离、无回滚点。** 改任何 harness 代码会立即影响运行中的实例。

**方案**：worktree + 独立实例端口，或至少确认无活跃用户 + 备份当前可用状态。

### 前置 B：dev 实例重启窗口

阶段 1/2/3 的每次改动要生效都需走 `deploy-dev.sh` 六步门禁（含第⑤步净室重启）。

**需要 owner 确认重启窗口。**
